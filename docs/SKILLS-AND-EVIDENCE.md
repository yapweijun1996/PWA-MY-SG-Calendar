## Auto Manager is different from Skill management

`agent:auto-manager` owns an already-authorized delivery outcome: bounded scope,
routine recovery, artifact inspection, independent acceptance and accurate reporting.
It does not self-authorize workers, model substitutions, release actions or registry
changes. This task requests research and documentation, so no workers were started.

`agent:skill-factory` owns the lifecycle of reusable procedures: evidence, duplicate
check, evaluation, reviewed promotion, versioning and routing verification. Reading
a project or discovering a lesson does not justify creating an enabled Skill.

The older coding/agent-systems hubs emphasize `agent:delegate-and-follow-up` as the
primary delegation manager; the newer exact search also exposes `agent:auto-manager`.
The latter explicitly composes the delegation workflow. Treat the hubs as indexes
that can lag newer entries, not proof that the newer enabled Skill is retired.
For an actual delegated task, read the relevant active procedures and host capabilities.

The UI hub contains differing historical notes about automatic registry loading.
Do not rely on a stale router assumption. Exact Skill search + get was used here;
any future router-based selection must inspect actual registry completeness and
route applicability. A tool being available does not establish authorization.
